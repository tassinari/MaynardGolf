# 18 — Handicap (calculator and data manager)

**Scope:** non-UI. How a player's handicap index is worked out, kept up to date and handed to every screen that shows it.
**Used by:** Home players (HOME-PLY-02), New round (NR-PLY-02), Players sheet (HP-PS-03), All players (AL-LS-01), Player card (PC-HDR-04…06, PC-HC-01…07), Handicap screen (19-handicap-screen), Add player (AP-HC-01…04).
**Replaces:** the v1 `Player.handicap` extension in `Handicap.swift`.

## 1. Overview
A player's index is the **calculated index** worked out from their completed rounds and outside scores using the World Handicap System (WHS). Until they have 3 usable rounds, the **starting index** typed in Add / Edit player stands in, and it seeds those first rounds' calculation (#268). The calculated index is never stored. A `HandicapManager` keeps every player's current index up to date and is the only place screens get it from, so all screens always show the same number.

## 2. Which index is shown
| ID | Requirement |
|----|-------------|
| HC-SRC-01 | **Calculated first:** with 3 or more usable rounds, the index calculated from them (§3) is the player's index everywhere, whatever starting index they have. |
| HC-SRC-02 | **Otherwise the starting index:** with fewer than 3 usable rounds, `Player.handicapIndex` (the starting index, AP-HC-02) when it's set (#268). It stops showing the moment a third usable round or outside score is saved. |
| HC-SRC-03 | Fewer than 3 usable rounds and no starting index → **no index**. Screens show "—". |
| HC-SRC-04 | The result is a `PlayerHandicap` value: `index: Double?`, `source: .calculated / .starting / .none`, and `roundsUsed: Int` (the usable rounds the calculation looked at, at most the newest 20). Screens format it with `displayText()` (the shared `DisplayFormatting.handicapIndex`); they never calculate. |
| HC-SRC-05 | Wherever the index is shown, a calculated value looks the same as a starting one, but its accessibility label adds "calculated" ("Handicap index 8.4, calculated"). The screens build that label from `source`. `PlayerHandicap.accessibilityNote` gives "calculated" (nil otherwise); Home's player cards put it in their label, and Home's player rows and New round's player rows set it as the row's accessibility value ("Mark, HCP 8.4" + "calculated"). All players and the Player card take it when they're built (phase 4). |
| HC-SRC-06 | Plus handicaps are stored negative and shown with a leading "+" ("+2.1"). Values are shown with one decimal. |

## 3. Calculation (WHS)
| ID | Requirement |
|----|-------------|
| HC-CA-01 | Rounds used: the player's **completed** rounds, newest first. Rounds in progress don't count. |
| HC-CA-02 | **Score differential** per round = (113 ÷ slope) × (adjusted gross − course rating), using the rating and slope of the **tee the player played** (course-maynard-gc §2). |
| HC-CA-03 | **Adjusted gross** caps each hole at net double bogey: par + 2 + strokes received on that hole. Strokes received come from the player's index at the time, as a WHS course handicap (index × slope ÷ 113 + (18-hole rating − par 70), rounded), spread over the holes by the hole's handicap for the round's hole count (CRS-HC-01…02): every hole gets the whole part, the hardest holes one more; a plus handicap gives strokes back from the easiest holes. Before the player has any index, each hole is capped at par + 5. |
| HC-CA-04 | **9-hole rounds** count, each one on its own, by filling in the other nine with an **expected score** from the player's index **before that round** (HC-CA-10; the WHS method since 2024). Its 18-hole differential = the **9-hole differential** actually played (HC-CA-09) + the **expected 9-hole differential** for the unplayed nine = 0.52 × index + 1.2. The result is used exactly like an 18-hole round's differential. |
| HC-CA-05 | **Index** = from the most recent 20 differentials, using the WHS table: 3 rounds → lowest 1 − 2.0; 4 → lowest 1 − 1.0; 5 → lowest 1; 6 → average of lowest 2 − 1.0; 7–8 → average of lowest 2; 9–11 → lowest 3; 12–14 → lowest 4; 15–16 → lowest 5; 17–18 → lowest 6; 19 → lowest 7; 20 → lowest 8. |
| HC-CA-06 | Rounded to one decimal, halves away from zero (8.25 → 8.3; a plus −2.05 → −2.1), capped at 54.0. |
| HC-CA-07 | Rounds with a missing hole score don't count (a completed round normally has all of them). |
| HC-CA-08 | `HandicapCalculator(course:)` is a pure, injected type: rounds (`HandicapRound`: date, hole count, tee, the player's strokes, finished or not; `HandicapRound.rounds(for:in:)` builds them from round snapshots) + course data in, `PlayerHandicap` out. No SwiftData, no dates from the system clock. It walks the usable rounds oldest first, so each round uses the index from before it. `calculatedIndex(rounds:upTo:)` gives the calculated index at a date for the history (HC-MG-06). |
| HC-CA-09 | **9-hole differential** = (113 ÷ slope) × (adjusted 9-hole gross − 9-hole course rating). The 9-hole rating is half the tee's 18-hole rating and the slope is the same (NR-TEE-06). The net-double-bogey cap uses the strokes received on those nine holes (half the course handicap, by the 9-hole hole handicaps, CRS-HC-02). |
| HC-CA-10 | **Which index:** the expected score uses the player's index as it stood **before that round**, not today's, so recalculating history never changes old results: the index calculated from their earlier rounds, or the starting index until there are 3 of them (HC-CA-14). Every differential, 18-hole or combined, is rounded to one decimal. |
| HC-CA-11 | **No index yet:** a 9-hole round played before the player has any index uses 54.0 as the index for the expected score, the WHS maximum, so their first rounds still count toward getting an index. |
| HC-CA-12 | **Outside scores** (#253, 12-data-model §3.5) count with the Maynard rounds. Each is a `HandicapRound` with `outside` set (no tee, no hole scores): its differential is (113 ÷ slope) × (gross − rating) with the rating and slope copied onto the score (DM-OS-06), and the posted gross as it is (there are no holes to cap). A 9-hole outside score works like a Maynard nine (HC-CA-04, 09…11): half the rating, the same slope, plus the expected nine from the index before it. It counts as played at its stored time, 12:00 UTC on its date (DM-OS-04), which orders it against a Maynard round the same day. Ids aren't unique-constrained (DM-RD-01), so a synced duplicate round or outside score counts once: the oldest copy (earliest start or creation), as `RoundRepository.round(id:)` picks it. |
| HC-CA-13 | **Breakdown** (`breakdown(rounds:)`, for the Handicap screen): the newest 20 usable rounds and outside scores, newest first, each with its differential, gross, hole count, tee (Maynard only), course name and whether it's one of the lowest the table averages (between equal differentials the newer counts). Also the calculated index, how many count and the adjustment. Always calculated, like `calculatedIndex`; both take the starting index only as the seed in HC-CA-14. The player's `PlayerHandicap` is derived from it (`handicap(startingIndex:breakdown:)`), so the rounds are walked once and the index always matches the list. |
| HC-CA-14 | **Starting index as a seed** (#268): for each round, the "index before" (its net-double-bogey cap, HC-CA-03, and a nine's expected score, HC-CA-10) is the index calculated from the earlier rounds, or, until there are 3 of them, the starting index when it's set, or the defaults (par + 5 per hole, 54.0) without one. Changing the starting index re-scores those early rounds, which stay in the newest-20 window. The breakdown, the index and the monthly series all use the same walk. |

## 4. Keeping it up to date (data manager)
| ID | Requirement |
|----|-------------|
| HC-MG-01 | `HandicapManager` (`@Observable`, on `AppDependencies.handicaps`) holds the current `PlayerHandicap` for every player and is the **only** source screens use: `handicap(for:)` gives a player's value, `.none` until it's ready. |
| HC-MG-02 | It recalculates a player when one of their rounds completes, is edited (Hole play edit mode) or is deleted, when their starting index is set or cleared, and when iCloud sync brings in changed rounds (found through persistent history, 12-data-model DM-SC-09). Only the affected players are recalculated. Local saves and iCloud imports both arrive on the change tracker's stream; after each batch that touches players, rounds, cards or outside scores, the manager reads fresh snapshots (`HandicapDataSource`: the background store, through a fresh context per read so a main-context save is never hidden by cached values) and recalculates only the players whose inputs changed: their starting index, their **finished, non-trashed** rounds or their outside scores (HC-CA-12) (so a stroke saved mid-round recalculates nobody). A player who's gone drops out. If two passes overlap, the newer one's result stands. A failed read is logged, `loadFailed` is set (a screen can offer `refresh()` as "Try again") and the current values stay. |
| HC-MG-03 | Screens update through observation: no reload, no notification. |
| HC-MG-04 | Calculation runs off the main actor (`@concurrent`) on value snapshots (DM-SC-07) and finishes in under 50 ms for a player with 200 rounds. Without course data, starting indexes still show and everyone else shows "—". |
| HC-MG-05 | On launch (`start(changes:)`, from the app shell), it calculates every player once, in the background, retrying a failed read after 1, 5 and 30 seconds. Until a player's value is ready, screens show "—" without a spinner. |
| HC-MG-06 | **History:** `series(for:months:)` returns the calculated index at the end of each of the last N months, oldest first (the current month ends now, from the injected clock), using only rounds and outside scores (HC-CA-12) played up to that date; months with fewer than 3 give no point. It feeds the Player card chart (PC-HC-04), which always shows calculated values. |
| HC-MG-07 | Nothing is stored. The manager can always rebuild every value from the rounds. |
| HC-MG-08 | `breakdown(for:)` serves each player's `HandicapBreakdown` (HC-CA-13), built in the same off-main pass as the index (which is derived from it, HC-CA-13) and observed the same way; `.empty` until ready, without course data, or for a player who's gone. |
